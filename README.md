# Reservation platform

A full-stack reservation system with invitation-only accounts, customer booking, and a separately deployed administrator backoffice.

## Applications

- `reservation-client` — Vue 3, TypeScript, Vite, Pinia, Tailwind CSS, shadcn-vue, and Capacitor.
- `reservation-admin` — standalone Vue 3 backoffice for administrator APIs.
- `reservation-backend` — Express, TypeScript, Prisma, PostgreSQL, Zod, and QR generation.

## Local setup

Start the complete web stack with Docker Compose:

```bash
docker compose up --build
```

The customer app runs at `http://localhost:5173`, the backoffice at
`http://localhost:5174`, the API at `http://localhost:3000`, and Directus at
`http://localhost:8055` (default login: `admin@example.com` / `change-me-now`).
Compose applies migrations and seeds the development administrator automatically.

Directus includes a **SQL Scripts** module for administrator accounts. Rebuild it
after changing the extension with `docker compose up -d --build directus`. Scripts
run directly against the application database, so take care with `UPDATE`, `DELETE`,
and schema changes.

To access the applications from another device on the same local network, use the
Docker Nginx gateway. The customer app is available on port `8080` and the admin
panel on port `8081`:

```text
http://<IP-DEL-PC>:8080
http://<IP-DEL-PC>:8081
```

Find the computer's LAN address with `hostname -I` on Linux. If push notification
links should open on another device, set `PUBLIC_ADMIN_URL=http://<IP-DEL-PC>:8081`
in `reservation-backend/.env`, then recreate the backend and gateway:

```bash
docker compose up -d --build backend admin lan-nginx
```

For HTTPS on the local network, generate the local certificate once with `mkcert`:

```bash
mkcert -install
mkdir -p nginx/certs
mkcert -cert-file nginx/certs/reservation.pem \
  -key-file nginx/certs/reservation-key.pem \
  reservation admin.reservation localhost 127.0.0.1 ::1
```

Add these entries to the `hosts` file of every device that will connect, replacing
the IP address with the LAN address of the Docker host:

```text
192.168.1.241 reservation admin.reservation
```

The HTTPS URLs are then `https://reservation:8443` for customers and
`https://admin.reservation:8443` for administrators. Direct IP access is also
available at `https://<IP-DEL-PC>:8443` for customers and
`https://<IP-DEL-PC>:8444` for administrators. The local CA generated by `mkcert`
must be trusted on each client device for Firefox to accept the certificate.

To start only PostgreSQL instead:

```bash
docker compose up -d postgres
```

Configure and start the API:

```bash
cd reservation-backend
cp .env.example .env
npm install
npm run db:generate
npm run db:deploy
npm run db:seed
npm run dev
```

In separate terminals, start the customer client and admin backoffice:

```bash
cd reservation-client
npm install
npm run dev
```

```bash
cd reservation-admin
npm install
npm run dev
```

The customer app runs at `http://localhost:5173`; the backoffice runs at `http://localhost:5174`. With the example environment, the local administrator is `admin@example.com` / `change-me-now`. Change these values before deployment.

Both frontend applications support Italian and English through `vue-i18n`. The initial language follows the browser and each application remembers its own selection.

## Verification

```bash
cd reservation-backend
npm run check
npm test
npm run test:smoke
npm run build

cd ../reservation-client
npm run typecheck
npm test
npm run build

cd ../reservation-admin
npm run typecheck
npm run build
```

The smoke test expects the API and PostgreSQL to be running. It verifies administrator login, invitations, customer registration, availability, booking, and overlap conflict handling.
